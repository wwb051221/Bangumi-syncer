# 匹配算法与人工复核

## 为什么需要启发式

飞牛用 TMDB 的标题（多为中文译名），Bangumi 用日文原名 + 中文名，两边**没有共享 ID**
（`item.external_ids` 实测全空）。所以只能按标题 + 年份 + 集数 + 季号打分。

设计取向：**宁可漏配，不可错配**。错配会把观看记录写到别人的条目上；漏配只是多一条待复核。

## 归一化（`matcher.normalize_title`）

1. NFKC 归一（全角 → 半角）；
2. **去掉季标记**：`第二季` / `第2期` / `第3部` / `Season 2` / `2nd Season` / `2期` /
   `第2クール` —— 这样「总之就是非常可爱 第二季」与「总之就是非常可爱」在标题层面等价，
   季号交给单独的加成/惩罚处理；
3. 去掉括号内容：`[TV版 多语版]`、`（2023）` 等；
4. 转小写、去掉标点与空白、`&` → `and`。

## 评分（0–1）

| 项 | 规则 |
| --- | --- |
| 标题 | 完全相等 `1.0`；包含关系 `0.90 × 长度比`；否则 `difflib 相似度 × 0.92`，取所有「本地名 × 候选名」的最大值 |
| 季号 | 候选标题解析出的季号 == 本地季号：`+0.04`（仅本季 ≥2）；不等：`−0.18`（没有季标记视为第 1 季） |
| 年份 | 相同 `+0.05`、差 1 年 `+0.02`、差 ≤2 `−0.04`、更远 `−0.15`；**本季 ≥2 时权重减半** |
| 集数 | 比例 ≥0.99 `+0.04`、≥0.8 `+0.02`、≥0.5 `−0.03`、否则 `−0.08` |

> 年份权重减半的原因：飞牛 TV 条目的 `first_air_date` 是**整部首播年**。例如
> 「总之就是非常可爱 第二季」（2023 年播出）在飞牛里年份是 2020，全额惩罚会把它推给第一季。

## 决策

```
best = 最高分候选
if best.score < match.min_score:            → 无法匹配（进复核）
elif best.score - second.score < min_margin: → 有歧义（进复核）
else:                                        → 自动映射（strategy=auto, confirmed=false）
```

默认 `min_score = 0.86`、`min_margin = 0.06`。人工映射 `strategy=manual, confirmed=true`，
永远优先于自动映射，并且可以用区间覆盖自动结果。

某库 13 季动漫，自动匹配结果：

| FX战士久留美 | 1 | 8 | ✅ 622288（0.97） |
| 总之就是非常可爱 | 2 | 12 | ✅ 355798 第二季（1.00） |
| 美少女战士 | 1 | 46 | ✅ 1510（1.00） |
| 茶啊二中 | 1–5 | 10/10/5/13/8 | ✅ 148295 / 148296 / 191336 / 241442 / 501710 |
| 药屋少女的呢喃 | 1 | 55 | ✅ 420628（0.97，合并季，见下） |
| 魔卡少女樱 | 1 | 70 | ✅ 1940（1.00） |
| 茶啊二中泡面番 | 1 | 21 | ⚠️ 复核（0.39） |
| 茶啊二中男寝501 | 1 | 19 | ⚠️ 复核（0.33） |
| 茶啊二中 嘎嘎以嘎斯 | 1 | 19 | ⚠️ 复核（0.22） |

后三条在 Bangumi 上没有独立条目，复核队列里保留候选由人工决定（通常是 `map remove` 或忽略）。

另外实测：`朱元璋`、`绝对权力`、`中国刑侦一号案` 这类国产电视剧在 Bangumi 上没有动画条目，
搜索会返回一堆不相关的番剧（相似度 0.2–0.4），因此**必须**用 `source.include_paths` 把
动漫库之外的内容排除在外——否则它们会不断污染复核队列。

## 合并季：区间映射

飞牛常把多季放在同一个 TV 条目、同一个 Season 里（例如「药屋少女的呢喃」S1 有 55 集，
实际对应 Bangumi 的三个条目）。程序发现「本地第 29 集 → 条目只有 24 集」时会记一条
`unmapped` 并提示拆分：

```
subject 420628 has 24 episode(s); local episode 29 maps to #29 - a split mapping may be needed
(fnos2bgm map add --series fnos:xxxx:s1 --subject <id> --from N --to M)
```

拆分示例：

```bash
fnos2bgm map add --account main --series 'fnos:xxxx:s1' --subject 420628 --from 1  --to 24
fnos2bgm map add --account main --series 'fnos:xxxx:s1' --subject 486347 --from 25 --to 48
fnos2bgm map add --account main --series 'fnos:xxxx:s1' --subject 568244 --from 49 --to 60
```

换算规则：`条目集号 = 本地集号 − ep_from + 1`，按条目章节的 `sort` 顺序定位（不依赖绝对集号），
所以即使 Bangumi 条目把第二季编成 13–24 集也能对上。

## 复核工作流

```bash
fnos2bgm review                      # 看候选、拿 series_key
fnos2bgm search -k "标题"            # 确认条目 id（可看年份/集数）
fnos2bgm map add --series '<key>' --subject <id> [--from N --to M]
```

`map add` 会自动清掉该区间的推送记录，下一轮重新按新映射推送；`review` 里对应条目随即消失。

如果某部番根本不打算同步（比如没有 Bangumi 条目），可以留着不管：复核队列不会自动做任何写操作，
它只是提醒。也可以用 `map remove` 清掉自动匹配后让它保持「复核」状态。
